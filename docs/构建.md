# 构建

在一台 Linux 机器上用 root 跑。Ubuntu / Debian 都行，x86_64 或 arm64 都可以。

## 一次性准备

```bash
# 1. 构建工具
sudo apt update
sudo apt install -y mmdebstrap debian-archive-keyring ubuntu-keyring \
                    curl gzip tar coreutils

# 2. 交叉构建 arm64 用（x86_64 机器上构建 arm64 包必须有这一步）
sudo apt install -y qemu-user-static binfmt-support
```

装完确认 binfmt 已注册：

```bash
ls /proc/sys/fs/binfmt_misc/ | grep qemu-aarch64
# 有 qemu-aarch64 就成了；没有就 sudo systemctl restart systemd-binfmt
```

> `mmdebstrap` 会自己往 chroot 里塞 qemu 二进制，不用手动拷。

## 构建

```bash
cd android-proot-rootfs

# 单个包
sudo ./build.sh debian-12 arm64 base

# 指定国内镜像（快 5~10 倍，强烈建议）
sudo ./build.sh ubuntu-24.04 amd64 base \
  --mirror http://mirrors.tuna.tsinghua.edu.cn/ubuntu

# 多个发行版（会按 ARCHES × TIERS 展开，默认 2 架构 × 3 档 = 6 个包）
sudo ARCHES=arm64 ./build.sh debian-12 debian-13
```

产物在 `out/`：

```
out/debian-12-arm64-base.tar.gz
out/debian-12-arm64-base.tar.gz.sha256
```

中途排查问题加 `--keep` 保留 `.work/` 目录。

## 各发行版的镜像地址

| 发行版 | 官方 | 清华 |
|---|---|---|
| Debian | `http://deb.debian.org/debian` | `http://mirrors.tuna.tsinghua.edu.cn/debian` |
| Ubuntu | `http://archive.ubuntu.com/ubuntu` | `http://mirrors.tuna.tsinghua.edu.cn/ubuntu` |
| Alpine | `https://dl-cdn.alpinelinux.org/alpine` | `https://mirrors.tuna.tsinghua.edu.cn/alpine` |

用镜像构建**没有副作用**：镜像里的包与官方一致，且 apt/apk 都会校验签名。

## 耗时参考（x86_64 机器，6 核）

| | amd64（原生） | arm64（qemu） |
|---|---|---|
| min | 40 秒 | 4 分钟 |
| base | 1.5 分钟 | 8 分钟 |
| dev | 4 分钟 | 25~40 分钟 |

arm64 的 dev 档最慢，建议晚上跑。

## 发布

```bash
# 1. 生成清单
./make-index.py --tag 2026.11
# 产出 out/index.json + docs/包清单.md（把后者一起提交）

# 2. 打 tag 发 Release
TAG=2026.11
gh release create "$TAG" \
  --repo ziwa0213-crypto/android-proot-rootfs \
  --title "rootfs $TAG" \
  --notes "见 docs/包清单.md" \
  $(ls out/*.tar.gz out/*.sha256)

# 3. 核验 latest 指向
curl -sI https://github.com/ziwa0213-crypto/android-proot-rootfs/releases/latest | head -3
```

**必须整批发布。** `releases/latest/download/<文件名>` 是稳定链接，如果哪次只传了一部分，
缺失的文件在那个 release 上会 404。

发了之后再补文件没必要：重建一个 release 更干净（`latest` 会切到新的）。

## 常见错误

**`unexpected end of stream` / 解压到一半报错**
下载被截断。检查 `.sha256`；构建侧已经用 `gzip -t` 和 sha256 拦住了，能出厂的都是完整的。

**`mmdebstrap: ... keyring ... No such file`**
`sudo apt install debian-archive-keyring ubuntu-keyring`。

**`qemu: command not found` / `Exec format error`**
交叉构建没装 qemu，或者 binfmt 没注册。见上面「一次性准备」。

**`mmdebstrap` 卡在 `I: running cmd`**
正常，它在跑 maintainer script。arm64 在 qemu 下尤其慢，别 Ctrl-C。

**`apk add` 报 `temporary error`**
网络抖动。脚本里自动重试 3 次；还失败就换 `--mirror`。

**chroot 相关报错**
必须在真机 / 完整 root 环境跑，容器里可能不行。

## 包里的约定

这些是应用侧（RikkaHub 工作区）依赖的，改之前先想清楚：

| 约定 | 原因 |
|---|---|
| 必须有 `/bin/sh` | 应用判断「这个 rootfs 能不能用」只看这一条 |
| `/etc/resolv.conf` 是普通文件，不是软链 | 软链指向宿主机的 `127.0.0.53`，proot 里解析不了 |
| 有 `/bin/bash` 就用 bash，否则 `/bin/sh` | 应用按这个顺序挑登录 shell |
| 用 `.tar.gz` 不用 `.tar.xz` | 应用端是纯 Java 解压，xz 慢 5~10 倍，手机上有明显卡顿 |
| 不带 `/dev` `/proc` `/sys` 内容 | 这三个由 proot 从宿主机的挂进来 |
| `/tmp` `/var/tmp` 是 1777 | proot 以 `--root-id` 运行，目录权限不对写不进去 |

## 在 Android proot 里构建（RikkaHub 工作区）

手机本身就是 `aarch64`，构建 arm64 包属于**原生编译**，不需要 qemu。
对照：x86_64 桌面用 qemu 模拟约 **195~198 秒/包**；骁龙 8 Elite 上实测
Debian 13 `base` **约 3 分钟**、Ubuntu 26.04 `minbase` **49 秒**、Alpine 3.24 `base` 72 秒。

proot 里本来就是 `uid=0`，**不需要 `sudo`**（`build.sh` 只检查 `id -u`）：

```bash
apt-get install -y --no-install-recommends \
  mmdebstrap debian-archive-keyring ubuntu-keyring python3
./build.sh debian-13 arm64 base --mirror http://mirrors.tuna.tsinghua.edu.cn/debian
```

### 四条在 proot 里必须知道的

1. **amd64 做不了。** `/proc/sys/fs/binfmt_misc/register` 不可写，注册不了 `qemu-x86_64`，
   x86_64 二进制无法透明执行。amd64 包只能在真机 / 桌面上构建。

2. **Debian 12 做不了。** `usrmerge` 靠硬链接把 `/bin` 并进 `/usr/bin`，
   proot 的 `--link2symlink` 会把硬链接改写成「存储文件 + 绝对软链」，
   `cp --no-dereference` 去拷时源头已不在 → `E: usrmerge failed`。
   Debian 13 / Ubuntu 已 usrmerged，绕开了这一步。

3. **没有 IPv6 的网络：apk 会报 `DNS: transient error`。**
   DNS 先返回 AAAA，musl 的解析器直接判失败（glibc 的 apt 不受影响）。
   `build.sh` 已把镜像域名的 IPv4 钉进 chroot 的 `/etc/hosts`，自动规避。

4. **proot 会丢硬链接文件。** `pack()` 只在检测到 `.l2s.` 残留时才做修正、才加
   `--ignore-failed-read`（真机上这两步完全空转），修正后会打印「跳过 N 个读不到的条目」。
   **N > 0 就说明产物不完整** —— 常见受害者是 `perl`、`unzip`、busybox applet。
   补救：从对应 `.deb` 里 `dpkg-deb -x` 取出实体文件补进去，重新打包。

> 结论：proot 里跑 Debian 13 这类「几乎不用硬链接」的发行版最稳；
> Alpine 的 apk 大量用硬链接，Ubuntu 26.04 的 uutils coreutils 是一百多个 applet 共用一个
> 10 MB 二进制的硬链接农场 —— 这两个在丢文件的 proot 里会直接缺 `ls`/`cat`，建议放到真机上构建。
